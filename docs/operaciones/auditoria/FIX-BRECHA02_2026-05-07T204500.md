# Fix BRECHA-02 — pipeline/views.py lee MariaDB correctamente

**Fecha:** 2026-05-07
**Archivo corregido:** `IACT-api/callcentersite/apps/pipeline/views.py`
**Commit IACT-api:** fix pipeline/views.py leer de MariaDB ivr_legacy

---

## Problema original

`etl_status` leia de `ETLExecution.objects.first()` — un modelo Django ORM
apuntando a PostgreSQL. Esa tabla estaba vacia. El historial real del ETL
en `job_execution_log` de MariaDB era completamente invisible desde la API.

```python
# ANTES (incorrecto):
from apps.pipeline.models import ETLExecution
last = ETLExecution.objects.first()   # siempre None — tabla vacia
```

## Solucion

Lee de `job_execution_log` en MariaDB via `connections['ivr'].cursor()`
segun UC_PIP_01.

```python
# DESPUES (correcto):
from django.db import connections
with connections['ivr'].cursor() as cursor:
    cursor.execute("""
        SELECT id, job_name, quarter_name, step_name, tabla_origen,
               start_time, end_time, status, records_procesados,
               duracion_seg, error_message, ejecutado_por
        FROM job_execution_log
        ORDER BY start_time DESC LIMIT %s
    """, [limit])
```

## Mapeo PipelineExecution (UC) → job_execution_log (IACT-db)

| Campo UC | Columna real | Tipo |
|---|---|---|
| id | id | int PK |
| source_table | tabla_origen | varchar |
| trimestre | quarter_name | varchar |
| started_at | start_time | datetime |
| finished_at | end_time | datetime |
| estado | status | enum(RUNNING/SUCCESS/PARTIAL/FAILED/SKIP/TIMEOUT) |
| base_records | records_procesados | int |
| error_message | error_message | text |
| executed_by | ejecutado_por | varchar |

## Logica ResumenSalud implementada

```
ok        — ultima exitosa dentro de las 14h
degradado — ultima exitosa entre 14h y 24h
critico   — ninguna exitosa en 24h o ultima es fallida
```
