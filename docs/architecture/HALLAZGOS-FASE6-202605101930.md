## H-F6-001 — `provision-mariadb.sh` omitido del plan original de T-6

**Tipo:** Alcance del plan  
**Severidad:** BAJA  
**Estado:** RESUELTO

### Descripción

El plan T-6.1..T-6.4 menciona tres archivos con changelog:
`schema_historico.sh`, `setup.sh`, `verify.sh`. `provision-mariadb.sh`
fue modificado en sesiones anteriores (H-EXEC-003: `local grant=` →
`GRANT_STMT=`) y quedó sin entrada de changelog.

Detectado originalmente como H-F5-004 durante FASE 5 con la recomendación
de actualizar FASE 6.

### Corrección aplicada

Entrada `v1.2.1 (2026-05-10)` agregada al bloque de changelog de
`scripts/provision-mariadb.sh`:

```
# v1.2.1 (2026-05-10):
#   · H-EXEC-003: corregido local grant= → GRANT_STMT= en bloque de grants DML.
#     local solo es válido dentro de funciones — con set -euo pipefail, el script
#     abortaba en línea 194 antes de otorgar los grants analíticos a django_user.
```

## H-F6-002 — Changelog de `schema_historico.sh` incluye FASE 3 (H-F3-001)

**Tipo:** Alcance ampliado respecto al plan  
**Estado:** DOCUMENTADO

### Descripción

El plan T-6.1 especifica: "Agregar entrada de versión nueva con los cambios
de FASE 0, 1 y 2". El changelog de v2.2.0 incluye también la corrección
de H-F3-001 (`(( consecutivos++ ))` → `(( ++consecutivos ))`):

```
#     FASE 3 — SKIP_SEED (H-F3-001):
#       · Fix (( consecutivos++ )) → (( ++consecutivos )) en verificar_estabilidad_mariadb
#               (( var++ )) con set -e cuando var=0 retorna exit 1 y mata el script
```

### Justificación

H-F3-001 fue detectado y corregido en `schema_historico.sh` durante la
ejecución de FASE 3. El fix está en el mismo archivo que las correcciones
de FASE 0, 1 y 2. Omitirlo del changelog de v2.2.0 habría dejado un cambio
de código sin registro en el archivo modificado. El criterio es: el
changelog del archivo refleja todos los cambios en ese archivo,
independientemente de en qué fase del plan se introdujeron.
